Introduction

Guaita Fitxers is a RVT and CAD file browser that runs entirely in the browser, without installing anything and without sending any data to a server. It reads the RVT version, the authorship (first and last editor), thumbnails and metadata directly from the file binary, and lets you manage files the way you would in the system file explorer.

A Chromium-based browser (Chrome or Edge) is required for all features. In other browsers only manual file selection in read-only mode works.

Opening a folder

When it starts, press Open a folder and choose the root folder you want to explore. The browser will ask for access permission. The folder tree on the left is then loaded.

If you had already opened a folder in a previous session, the ↩ Back to… button appears to reopen it quickly (you only need to confirm the permission again).

The two trees

Guaita Fitxers has two independent folder trees:

  • Source tree (left): you browse the folders and see their contents in the central panel. Its header contains the 📂 Root folder button, the ↻ refresh button and the current path.
  • Destination tree (right, yellow 📂 Destination folder button): used only as a destination for copying or moving files. It shows no files, only folders, and can be on a different drive from the source. It is opened and hidden with the ◨ Destination control button.

Both trees can be resized by dragging the divider, have ◄ ► buttons to go back and forward through the navigation history, and show the SBS BIM Consulting signature at the bottom.

File information

Formats and filters

Each file is shown with a type tag and, when it can be read, the version:

Format details for the 3D · Point clouds group:

  • IFC: schema (IFC4, IFC2X3…) and file author.
  • DXF: format version, drawn thumbnail and an interactive viewer in the detail card.
  • E57: version, sensor manufacturer and model, number of scans and total points.
  • XYZ · PTS: point count and thumbnail with the projection of the cloud.
  • OBJ: vertices, faces, material library and a vertex thumbnail.
  • GLB · glTF: version, generating program and counts of meshes, nodes and materials.
  • 3DM: Rhino version and preview embedded in the file.
Very large files (point clouds, OBJ) are read only up to the first 2 MB: the counts and thumbnails for these cases are marked as sample.

The format chips in the filter bar let you choose what to see. They can be combined. The All chip works in two ways: the first click selects all known formats and the second clears all of them (no format). The *.* chip shows any file, whatever its type.

The ✎ other chip filters by custom extensions: type them in the field next to it separated by semicolons (.bak; .log; .csv) and press Enter. They are remembered between sessions, and the chip turns them on or off without retyping. The alert chips filter only files with ⚠ multi (more than one editor), ⚠ central (worksharing model) or ≡ dups (duplicates).

The ⤵ Subfolders chip scans recursively the whole tree below the active folder. The search box filters by file name, subfolder or editor name.

RVT backups

RVT leaves backups with the pattern NAME.0040.rvt or FAMILYNAME.0003.rfa (dot, four digits, dot, extension) that fill working folders. The ⧉ Backups chip manages them and has three states, which are remembered between sessions:

  • Stacked (default): they do not appear as loose files, but grouped under their main file with a blue badge that shows how many there are and the dates of the first and the last one. Clicking the badge opens all of them with the number, date and size.
  • Hidden: they disappear from the list.
  • Visible: they are listed like any other file (needed if you want to select them to delete or move them).
Stacking only groups backups that are in the same folder as their main file. A backup whose main file is missing (because it was moved or deleted) continues to be shown as a normal file, so that no information is hidden without warning.

The Backups, First backup and Last backup columns are also exported to TSV.

Sorting

The Sort by selector offers simple criteria (name, type, version, size, date, saves, first editor, last editor) and chained combinations, such as “Version → Type → Date”: when the first criterion ties, the next one breaks the tie. The ↓/↑ button reverses the direction. In table view you can also sort by clicking the column headers.

Thumbnails

Thumbnails are extracted from the file. Click on one to see it enlarged at twice the size. With the ⬇ PNG button you download the thumbnail. With 🖼 Change you can replace the thumbnail of a RVT file with an image of your own (a .bak copy is created automatically before anything is modified).

Details and history

With a file selected, press Space to open the detail card: large thumbnail, version, build, path, hash, central model path and the full history of saves, plus the metadata specific to each format (pages, author, dimensions, points, meshes…).

Some formats add a viewer:

  • DXF: interactive viewer with wheel zoom and drag to pan.
  • PDF: the complete native browser PDF viewer, with all pages and zoom.
  • Images: preview at large size.

The number of saves is clickable and opens the full history of edits. The ≡ duplicate badge opens the group of identical files (same content byte for byte).

File management

Selection

It works like the system file explorer:

  • Single click: selects a file.
  • Ctrl + click: adds or removes from the selection.
  • Shift + click: selects a range.
  • Ctrl+A: selects everything; Esc clears the selection.

Copy, move, delete

When pasting into the same folder, conflicting names receive the suffix “- copy”. Large operations show a progress bar with the current file, the MB transferred and the speed, and can be cancelled.

Deletion is permanent: it does not go to the recycle bin. It asks for confirmation and is recorded in the log, but it cannot be undone.

Drag and drop

You can drag files (and folders from the tree) to any folder in either tree. When you drop them:

  • With Ctrl: direct copy.
  • With Shift: direct move.
  • With no modifier: a small menu appears to choose Copy here or Move here.

The File tray (inside Guaita apps)

When Guaita Fitxers runs inside the Guaita apps launcher, you can send files to the File tray — the shared repository at the bottom of the sidebar — and open them from there with any other Guaita tool. There are two ways:

  • 📤 button: select one or more files and press the 📤 in the toolbar (next to 🗒). The selection appears in the tray as chips.
  • Drag: take a file (or the selection) and drop it on the tray, on the chip of an app in the side list (it opens with the loaded file) or on the window of an app that is already open.
The 📤 button and this drag out only exist inside the launcher; if you open Guaita Fitxers alone in the browser they are not there and everything else works the same. The internal drag to copy or move between folders does not change.

Folders and renaming

The ➕📁 button creates a folder in the active folder; ➕📁 New folder in destination creates one in the destination tree. To rename, select a file and press F2 (or the ✏ button); to rename a folder, double-click it in the tree.

Undo and log

The ↩ button (or Ctrl+Z) undoes the last copy, move, rename or create-folder operation. The 🗒 button shows the log of all operations in the session, exportable to TSV.

The bridge to RVT

An HTML page cannot open programs or the system file explorer on its own. To do so, Guaita Fitxers can connect to a small Python program (guaita_fitxers.py, in the bridge/ folder of the repository) that you run on your computer. When it is active, the ⛭ bridge indicator turns green and shows the RVT versions detected.

The bridge listens only on 127.0.0.1 (your own computer). It makes no connection to the outside.
The bridge only accepts requests from the published app (subi2.github.io) and from localhost. Pages from other websites cannot use it, and it only operates on RVT files (.rvt .rfa .rte .rft). If you open the app as a local file (file://), the bridge is not accessible.

So that the bridge knows where the files really are, you must type once the absolute path of the root folder (for example E:\ENTREGUES) in the field next to the indicator. For privacy, the browser does not reveal this path by itself.

Open with RVT

With the bridge active, each RVT file has a version selector and the ▶ Open button, which starts the chosen RVT version with that file. By default the version the file was saved with is selected.

Locate and copy path

  • 📂 Locate: with the bridge active, opens the system file explorer with the file highlighted. Without the bridge, it copies the containing folder to the clipboard so that you can paste it into the address bar.
  • 🔗: copies the file path to the clipboard. If you have entered the root path, it copies the full absolute path; otherwise, the relative one.

Privacy

All processing is local: reading metadata, thumbnails, hashes and file operations happen in your browser. No file or data leaves your computer. The only possible connection is with the Python bridge, which runs on your own machine.
